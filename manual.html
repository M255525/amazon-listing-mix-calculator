操作手冊

輸入多個分類、多項商品的售價與銷量，毛利自動算出並套用 Amazon 各分類抽成％算出抽成後淨利，跟公司固定支出門檻比對是否收支平衡，並依補貨前置期抓出需要優先補貨的商品、依銷售貢獻拆出商品組合陳列角色。

操作步驟

  1. 先點一個貼近你情境的快速範例按鈕，會套用整組門檻、分類與商品資料；之後可以再自行新增/刪除/編輯任何一列
  2. 在「全域設定」填入公司每週／每月最低獲利門檻（也就是固定支出，例如房租、人事、倉儲）、補貨所需天數（前置期），以及美元／日圓兌台幣匯率（用來把商品售價換算成台幣）；「平台上架總金額上限」是你自己想設的庫存投入金額警戒線，並非 Amazon 官方硬性規則，不需要就不用勾選啟用
  3. 在「分類與抽成設定」新增分類並填入該分類的 Amazon 抽成％（referral fee，多數分類約 15%，請依實際分類確認）
  4. 在「商品清單」逐項填入品名（選填）、所屬分類、庫存數量、週／月銷售數量；「建議售價」與「建議售價(NT$)」只要擇一填寫即可（見下方「售價欄位與匯率換算」說明）；週／月毛利不用手動輸入，會自動以「建議售價(NT$) × 銷量」即時算出
  5. 也可以直接按「📤 上傳CSV／Excel」匯入整批商品（見下方「匯入／匯出商品清單」說明），不必逐列手動輸入
  6. 「結果儀表板」會即時算出總週／月淨利（毛利已扣除該分類抽成）跟門檻的比對、上架總金額（已換算台幣）、補貨警示清單、分類別彙總比較
  7. 「商品組合陳列角色」會依每項商品的月淨利貢獻度，自動歸類到主力／輔助／附屬／聯想／刺激商品五種角色，供你規劃賣場陳列與資源分配參考
庫存可撐天數＝庫存數量 ÷（週銷售數量 ÷ 7）。可撐天數低於補貨所需天數＝緊急補貨；低於補貨所需天數的1.5倍＝注意；週銷售數量為 0 的商品不計算可撐天數（無銷售紀錄）。

售價欄位與匯率換算

商品清單裡「建議售價」與「建議售價(NT$)」只要填一個就好：

  • 填「建議售價」（美金 USD 或日幣 JPY，對應 Amazon.com／Amazon.co.jp 的實際上架幣別）→ 會依全域設定的匯率自動算出「建議售價(NT$)」，並覆蓋掉該欄位原本的數字
  • 不確定美金/日幣售價、但已經知道台幣參考價 → 可以跳過「建議售價」，直接在「建議售價(NT$)」填台幣金額，一樣能用
  • 兩個都填也可以，但「建議售價(NT$)」才是實際拿去計算的數字——只要你之後又改了「建議售價」或幣別或全域匯率，「建議售價(NT$)」都會被重新算過、蓋掉你先前手動填的數字

「建議售價(NT$)」會再乘上週／月銷量，自動算出「毛利（週／月）」（唯讀，不用手動輸入），也會乘上庫存數量累加成「上架總金額」KPI 卡，拿去跟「上架總金額上限」比對。

全部商品都沒填「建議售價」或「建議售價(NT$)」的話，毛利與上架總金額都會是 0——這兩個欄位現在是驅動毛利計算的關鍵輸入，不再只是選填的參考資訊。

匯入／匯出商品清單（CSV／Excel）

按「📤 上傳CSV／Excel」可選擇 .csv、.xlsx 或 .xls 檔案，系統會讀取第一列的欄位標題自動對應到下列欄位（標題文字有一定彈性，例如「售價」「價格」「建議售價」都能對到售價欄位）：

  • 品名、分類、建議售價、售價幣別（USD／JPY，留空預設 USD）、建議售價(NT$)、庫存數量、週銷量、月銷量

「建議售價」跟「建議售價(NT$)」一樣只要有一欄有值就好——只填「建議售價」會依當下的匯率自動算出台幣欄；只填「建議售價(NT$)」則直接採用你給的台幣數字。週／月毛利不是匯入欄位（匯入後會自動算出），就算上傳的檔案裡有這兩欄也會被忽略。匯入時「分類」欄位的文字會自動比對現有分類名稱，找不到就自動新增一個抽成 15% 的新分類；匯入完成後會取代目前畫面上的商品清單（分類不會被清除，只有商品清單會被取代）。按「📥 下載商品清單CSV」可以把目前畫面上的商品清單（含分類名稱、幣別、自動算出的週／月毛利供參考）匯出成 CSV，方便離線用 Excel 編輯後再重新上傳。

CSV 讀取採用 UTF-8 編碼；如果從其他系統匯出的 CSV 開啟後中文變亂碼，建議先用 Excel 另存成「CSV UTF-8」格式再上傳。

商品組合陳列角色是怎麼算的？

依「月淨利貢獻度」做類似 ABC 分析的排序，再搭配分類關聯性、售價與月銷量的簡化規則，把每項商品歸到下列五種角色：

  • 主力商品：完成銷售量或銷售金額在銷售業績中占舉足輕重地位的商品（月淨利累計貢獻前 60% 的商品）
  • 聯想商品：與主力商品具有很強的關聯性（跟某項主力商品同分類、且貢獻在中段的商品）
  • 輔助商品：在價格、品牌等方面對主力商品起輔助作用，或以增加商品寬度為目的的商品（跟主力商品不同分類、貢獻在中段的商品）
  • 刺激商品：品項不多，但對推動賣場整體銷售效果意義重大的商品（貢獻偏低但售價偏低、月銷量偏高的商品）
  • 附屬商品：輔助商品的一部分，對顧客而言是易於購買的目的性商品（貢獻偏低、不符合刺激商品條件的其餘商品）
這是簡化的規則式分類，僅供參考，不是絕對正確的商品定位判斷；商品數量太少（例如只有 1-2 項）時分類意義有限。

請 AI 診斷收支狀況與商品搭配陳列

沒有 API 金鑰也能用：直接按「改用規則式健檢」，會依目前的收支平衡、補貨警示與商品角色分類，組出對應的健檢建議與搭配陳列建議，不需要連網。

想要更貼近你情境的診斷，可以展開「AI 診斷設定」，選擇服務商（Claude／OpenAI／Gemini／OpenRouter）並填入你自己的 API 金鑰，按「請 AI 診斷目前的商品組合」。

診斷區塊上方有 5 個「診斷角度」快速按鈕，點選後會把對應的提示文字帶入下方文字框，留空則走一般整體健檢：

  • 整體收支健檢：總體健檢收支平衡與各分類獲利表現，點出最大風險與機會
  • 補貨優先順序建議：依補貨警示給出補貨優先順序與資金分配建議
  • 滯銷商品處置建議：找出銷售偏低或周轉過慢的商品，建議出清、降價或下架
  • 分類抽成優化：分析各分類抽成對淨利的侵蝕程度，建議調整定價或分類
  • 新品上架規劃：依商品組合角色分布，建議接下來適合新增哪種角色定位的商品
不論選哪個角度，每次送給 AI 的請求都會固定附上商品組合陳列角色分類，並要求 AI 具體建議商品搭配陳列方式（例如哪些商品該相鄰陳列、哪些該做組合促銷、如何用刺激商品或聯想商品帶動主力商品曝光）——這是本工具設計時的既定行為，不需要另外點選按鈕。文字框內容可以自行編輯或清空。AI 呼叫失敗時（例如金鑰無效）會自動退回規則式健檢，不會沒有內容。

匯出 PDF 或 Word

頁尾按「🖨️ 匯出PDF」，會開啟瀏覽器的列印視窗，選「另存為 PDF」即可把目前的試算內容存成 PDF 檔；按「📝 匯出Word」則會直接下載一份 .docx 檔案，兩者內容一致，格式自行選用。匯出時會自動：

  • 把整體收支概況（含匯率設定、上架總金額）、分類別彙總、補貨警示、商品組合陳列角色整理成一份報告（畫面上的互動表格不會出現在報告裡）
  • 加上「馬克老師」浮水印與產生時間戳記，提醒這份輸出是估算工具的結果，不是正式財務報表；PDF 浮水印置中顯示，Word 浮水印則置於每一頁的頁首區域、文字下方
如果曾經產生過 AI 診斷結果，該段診斷與搭配陳列建議也會一起出現在 PDF 與 Word 裡；沒有產生過就不會出現這個區塊。「📝 匯出Word」第一次點擊時會從 CDN 載入約 1MB 的 docx 產生元件，需要網路連線；之後同一次瀏覽階段內不用重新下載。

加入主畫面（可選）

頁面右上角按「📲 加入主畫面」，可以把這個工具像 App 一樣安裝到手機或電腦桌面，之後不用開瀏覽器輸網址就能直接點圖示開啟。

  • Android（Chrome）／桌面 Chrome、Edge：按下按鈕會直接跳出安裝確認視窗
  • iPhone／iPad（Safari）：按下按鈕會提示改用「分享」圖示 → 「加入主畫面」（iOS 系統限制，無法由網頁直接跳出安裝視窗）
  • Mac 桌面版 Safari：會提示改用選單列「檔案」→「加入 Dock」（Safari 17 以上）
安裝與否不影響任何功能，純粹是操作方便性；不安裝、直接用瀏覽器開網址一樣可以完整使用。

  • AI 金鑰同樣只存在瀏覽器的 localStorage；按下「請 AI 診斷」且有填金鑰時，你的試算資料會直接連線送到你選擇的服務商官方 API，不會經過本工具作者或任何第三方伺服器
  • 「匯出Word」「上傳CSV／Excel」功能第一次使用時，會從公開 CDN（jsDelivr／cdnjs）載入對應的 JavaScript 元件，除此之外的操作都不需要網路連線

使用警語

請注意：
  • 本工具的試算結果皆為估計值，不是正式財務報表，也不是專業財務、稅務或法律意見，不能取代會計師或供應鏈顧問
  • 「平台上架總金額上限」為你自訂的參考門檻，並非 Amazon 官方硬性規則；商品組合陳列角色為簡化規則式分類，僅供參考
  • 匯率為你自行輸入的固定數字，不會自動連線查詢即時匯率，請自行更新以反映實際匯率波動
  • 上傳 CSV／Excel 匯入商品清單會取代目前的商品清單，請先自行備份（可用「下載商品清單CSV」）再匯入

  • AI 生成的診斷內容可能包含錯誤或不合時宜的建議，實際決策前務必自行檢查與查證
  • 使用 AI 診斷功能所產生的 API 費用由你與所選服務商的方案自行負擔，本工具不會向你收費
